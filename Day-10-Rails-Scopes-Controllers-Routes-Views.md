# Day 10 — Rails Scopes, Controllers, Routes, and Views

## Learning goals

By the end of this lesson, you should understand how to:

- Define a reusable scope in a Rails model.
- Call the scope from a controller action.
- Add a collection route for a custom page.
- Display the results in an ERB view.
- Follow a request from the browser through routes, controller, model query, and view.

---

## 1. Create a scope in the model

**File:** `app/models/product.rb`

```ruby
class Product < ApplicationRecord
  scope :whitelisted_products, -> {
    where("stock <= ?", 25)
  }
end
```

### What is a scope?

A **scope** is a named, reusable Active Record query defined in a model.

- `whitelisted_products` is the scope's name.
- `where("stock <= ?", 25)` filters products whose stock is 25 or less.
- The `?` is a parameter placeholder. Active Record safely binds the value instead of inserting it directly into the SQL string, helping prevent SQL injection.
- `whitelisted_products` is just the name chosen for this example; it does not itself provide a security allowlist.

The query is conceptually equivalent to:

```sql
SELECT * FROM products WHERE stock <= 25;
```

Example records:

| Product | Stock | Returned? |
|---|---:|---|
| Laptop | 50 | No |
| Mouse | 10 | Yes |
| Keyboard | 25 | Yes |
| Monitor | 5 | Yes |

The scope includes stock values equal to 25 because `<=` means “less than or equal to.”

### Calling the scope

```ruby
Product.whitelisted_products
```

This returns an Active Record relation representing products that match the condition. Rails generally runs the SQL when the records are needed, such as when the relation is iterated over or loaded.

> If `stock` is `NULL`, SQL's comparison `stock <= 25` does not match that row, so it will not be returned by this condition.

## 2. Use the scope in a controller

**File:** `app/controllers/products_controller.rb`

Add this action inside the existing `ProductsController` class:

```ruby
def whitelisted_products
  @products = Product.whitelisted_products
end
```

### What happens?

1. `Product.whitelisted_products` calls the model scope.
2. The query represents products with stock of 25 or less.
3. The result is assigned to the instance variable `@products`.
4. Rails conventionally renders the matching view for this action.

### Why use `@products`?

The `@products` instance variable is available to the view rendered by this controller action. The view can iterate over it and display the records.

It is not automatically available to every view; it is available to the view rendered in this controller request and relevant partials rendered in that context.

---

## 3. Add a collection route

**File:** `config/routes.rb`

```ruby
resources :products do
  collection do
    get :whitelisted_products
  end
end
```

### Understand the route

- `resources :products` defines the standard RESTful product routes.
- `collection do` adds a route for the products collection as a whole. It does not require an individual product ID.
- `get :whitelisted_products` defines a GET route for the custom action.

The route is typically:

```text
GET /products/whitelisted_products
```

It maps to:

```text
ProductsController#whitelisted_products
```

You do not need to write `resources :products` a second time. Put the custom collection route inside the existing products resource declaration.

### Verify the route

Run this from the Rails project directory:

```bash
rails routes | grep whitelisted_products
```

You can also run:

```bash
rails routes
```

Check the output for the HTTP verb, URL path, controller action, and route helper name. `rails routes` is the reliable way to confirm the helper generated by your application.

## 4. Create the view

**File:** `app/views/products/whitelisted_products.html.erb`

```erb
<h1>Whitelisted Products</h1>

<% @products.each do |product| %>
  <p>
    <%= product.name %> — Stock: <%= product.stock %>
  </p>
<% end %>
```

This example assumes the `products` table has `name` and `stock` columns.

### ERB syntax

| Syntax | Meaning |
|---|---|
| `<% ... %>` | Executes Ruby code without displaying its return value. |
| `<%= ... %>` | Executes Ruby code and displays the result in the rendered HTML. |

In the example:

- `@products.each` loops through the filtered products.
- `product.name` reads a product's name.
- `product.stock` reads its stock value.
- `<%= ... %>` displays each value in the page.

The view does not need to filter the records again. The model scope defines the query, and the controller assigns the result to `@products`.

Rails conventionally renders `app/views/products/whitelisted_products.html.erb` for the `whitelisted_products` action unless the action specifies a different response or rendering target.

## 5. Complete request flow

When a user opens:

```text
http://localhost:3000/products/whitelisted_products
```

the request flows through the application like this:

1. **Browser:** Sends a GET request to `/products/whitelisted_products`.
2. **Routes:** Matches the route and directs the request to `ProductsController#whitelisted_products`.
3. **Controller:** Calls `Product.whitelisted_products`.
4. **Model scope / Active Record query:** Builds and runs the query for products where `stock <= 25`, when the records are needed.
5. **Controller:** Makes the result available as `@products`.
6. **View:** Iterates over `@products` and renders the product details as HTML.
7. **Browser:** Displays the resulting HTML page.

### Quick flow diagram

```text
Browser request
      |
      v
Rails routes
      |
      v
ProductsController#whitelisted_products
      |
      v
Product.whitelisted_products
      |
      v
Active Record query: stock <= 25
      |
      v
@products
      |
      v
whitelisted_products.html.erb
      |
      v
HTML response to browser
```

## 7. Key takeaways

- **Model scope:** Reusable query logic.
- **Controller action:** Calls the scope and prepares data for the view.
- **Collection route:** Creates a custom route for the collection without a product ID.
- **ERB view:** Displays data using Ruby and HTML.
- **Request flow:** Browser → Routes → Controller → Model query → View → Browser.

Remember: `whitelisted_products` is just an example scope name. It filters by stock in this lesson; it does not mean the records have been security-approved.

## 8. Quiz review and answers

### Concept 1 — Model scope

**Question:** Given Laptop (50), Mouse (10), Keyboard (25), and Monitor (5), what does `Product.whitelisted_products` return?

**Answer:** Mouse, Keyboard, and Monitor. Their stock values are all less than or equal to 25.

### Concept 2 — Controller

**Question:** What is the purpose of `@products` in `@products = Product.whitelisted_products`?

**Answer:** It stores the scope result so the corresponding view can access and display the products.

### Concept 3 — Collection route

**Question:** What is the purpose of `collection`?

**Answer:** It adds a route for the products collection without requiring a specific product ID.

### Concept 4 — ERB

**Question:** What is the difference between `<% ... %>` and `<%= ... %>`?

**Answer:** `<% ... %>` executes Ruby without displaying its return value. `<%= ... %>` displays the evaluated result in the HTML.

### Concept 5 — Request flow

**Question:** What is the correct request flow?

**Answer:** Routes → Controller → Model scope/query → View.
